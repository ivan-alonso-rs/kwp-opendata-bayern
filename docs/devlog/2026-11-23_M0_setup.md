# Devlog – M0 Project setup (2026-11-23)

## What I did
- Created the GitHub repository and set up a separate Git identity for this
  project, so my commits are not mixed with another account I use.
- Installed PostgreSQL 18 with PostGIS 3.7.0 and created the database `waermeplanung`.
- Built the Python environment `kwp` from `environment.yml` (conda-forge).
- Created a `.env` file for the database password and ran the setup check.

## What I learned
- My setup was not what I thought: the old conda environment `gis` did not exist
  and PostgreSQL was not installed. Checking the environment first saved me from
  debugging data problems later that were really installation problems.
- conda-forge is the safer channel for geospatial packages: GDAL, PROJ and GEOS
  have to be built together, and mixing channels causes DLL errors on Windows.
- `psql` first asks for connection settings (server, database, port, user).
  SQL commands only work after the `postgres=#` prompt appears.
- Passwords belong in `.env`, which is listed in `.gitignore`, so they never reach GitHub.
- `git config` without `--global` sets an identity only for one repository.
- `pip install -e .` installs the project package in "editable" mode. If it is
  skipped, scripts cannot import `kwp` – we fixed the check script so it also
  works without it.

## Problems and how I solved them
| Problem | Cause | Solution |
|---|---|---|
| `psql` not recognized | PostgreSQL was not installed | Installed PostgreSQL 18 + PostGIS via StackBuilder |
| `CREATE DATABASE` failed in SQL Shell | I typed SQL into the connection prompts | Pressed Enter for the defaults, then ran SQL at `postgres=#` |
| conda environment `gis` not found | It never existed / was broken | New environment `kwp` from `environment.yml` |
| "config loads" and DB check failed | Local package `kwp` was not installed | `pip install -e .` + script fix (adds `src/` to the path) |
